# concept-explainer — 概念学习资料生成 Skill

## 1. 适用场景

当用户提出下面任一请求时，加载并按本 Skill 的流程执行：

- "帮我系统了解一下 X 这个概念"
- "用学习资料的方式给我讲一下 X"
- "把 X 整理成一份可以发布的笔记"
- "我对 X 一知半解，给我一份能让我向别人讲清楚的资料"

不适用：

- 用户只是随口提问、想要一句话答案。
- 用户要求的是代码示例、API 用法演示（那应交给代码类 Skill）。
- 用户的主题不是概念、术语或方法论，而是具体业务需求。

## 2. 输入信息（必填 + 可选）

**必填**：

- `concept`：要学习的概念名称（中英文皆可；如果是英文缩写，先展开全称）。

**可选（强烈建议填，否则自检更严）**：

- `level`：受众水平（beginner / intermediate / advanced），默认 `intermediate`。
- `prior_knowledge`：用户已掌握的先验知识，避免重复铺垫。
- `angle`：希望侧重哪个角度（如 "工程实现"、"历史脉络"、"数学原理"），默认综合。
- `output_path`：HTML 输出路径，默认 `learning-materials/<concept-kebab-case>.html`。

调用 Skill 时如果用户没指定，按默认执行，并在产出末尾注明"已采用默认参数"。

## 3. 生成步骤（按顺序执行）

1. **概念锁定**：明确 `concept` 的最权威定义，给出英文全称、首次提出者或出处。
2. **个人解释**：用第一人称、口语化、亲历者角度解释这个概念（"我把它理解为..."），避免论文腔。
3. **核心机制或组成**：拆解 2–5 个核心组件 / 步骤，给出最小但完整的工作流；能用伪代码、流程图或 ASCII 示意更好。
4. **一个具体应用场景**：描述一个真实可触达的案例（产品 / 系统 / 论文 demo），把概念"用起来"。
5. **容易混淆的问题或使用边界**：列出 3–5 条最容易踩的坑、被滥用场景、与相邻概念的边界（如 Agent vs Chatbot）。
6. **资料来源链接**：给出 3–6 条**可核查**的链接，优先官方文档、原始论文、知名工程团队的博客；标注每条链接的"可信度"（官方 / 学术 / 工程 / 一般）。
7. **自检**：跑一遍第 6 节的自检清单，全部通过才能交付。
8. **写入文件**：把整篇内容渲染为单文件 HTML（见第 4 节结构），写到 `output_path`。

## 4. 输出结构（HTML 模板）

每个 HTML 必须包含以下五个一级章节（顺序固定，标题可中英混排，但锚点 ID 必须保留）：

```
<article>
  <section id="personal">     <!-- 个人解释 -->
  <section id="mechanism">    <!-- 核心机制或组成 -->
  <section id="scenario">     <!-- 一个具体应用场景 -->
  <section id="confusion">    <!-- 容易混淆的问题或使用边界 -->
  <section id="sources">      <!-- 资料来源链接 -->
  <footer id="meta">          <!-- 生成时间、所用 Skill 版本、人工核查记录 -->
</article>
```

CSS 风格：浅色主题（IDE 为 light 时）、卡片化、最大宽度 880px、章节用 `<details>` 或清晰的标题分隔。代码块用 `<pre><code>`，引用用 `<blockquote>`。不依赖付费 CDN。

## 5. 资料来源要求（硬约束）

- **必须**给真实、可点开的 URL，不得编造。
- **必须**至少包含 1 条官方文档或原始论文。
- 链接文字要让读者预判内容，不要写"链接1"、"参考1"。
- 每条链接后注明"可信度"：🟢 官方 / 🔵 学术 / 🟡 工程博客 / ⚪ 一般。
- 自检时如果发现链接 404 或可疑，立即修正或删除。

## 6. 自检清单（交付前必跑）

- [ ] 五个一级章节齐全且顺序正确。
- [ ] "个人解释"段是第一人称口语化，没有"本文将..."这种论文腔。
- [ ] "核心机制"含至少 2 个组件或步骤。
- [ ] "应用场景"是具体可触达的，不是"比如 AI 客服"这种泛指。
- [ ] "混淆与边界"至少 3 条，每条用一句话说清边界。
- [ ] "资料来源"链接全部能点开，至少 1 条官方/学术来源。
- [ ] HTML 文件能直接在浏览器中打开渲染（无未闭合标签、无 JS 报错）。
- [ ] 文件路径符合 `output_path` 默认或用户指定。

## 7. 工作约定

- 本 Skill 不调用任何外部 API，所有内容由当前 AI 基于公开知识生成；资料链接必须经得起点开核查。
- 如果对概念本身不确定，**诚实标注"存疑"**，不要硬编。
- 与"概念关系说明"配合使用：当用户要求解释一组相关概念时，本 Skill 负责单概念 HTML，关系说明由专门模板（见 `learning-materials/concept-relationship.html`）承担。
