Agent — 不只是"会聊天的 AI"

生成于 2026-09-06 · Skill concept-explainer v1.0

1. 个人解释

我第一次把 Agent 想明白，是在我用 AutoGPT 让它自己上网订机票的时候。我给它一个目标"帮我订一张明天从北京到上海、最便宜的红眼航班"，它自己拆任务、自己去查航班、自己比对价格、自己填表下单。我盯着屏幕那一刻我才意识到：哦，这跟 ChatGPT 完全不是一种东西。

我后来给 Agent 下过一个朴素的工作定义：Agent = 能感知环境 → 自己做决策 → 自己采取行动的 AI 系统。它跟我直接聊天的 Chatbot 最大的区别在于：Chatbot 是"我问你答、你说我听"，Agent 是"你给目标，它自己干"。它的关键不在于"有没有 LLM"，而在于"有没有自主行动的能力"。

2. 核心机制或组成

拆开看，一个能用的 Agent 通常包含四块：

  1. 规划（Planning）：拿到目标后，先拆解成子任务。比如"订机票"会被拆成"查航班 → 比价 → 选航班 → 填乘客信息 → 付款"。
  2. 工具（Tools）：调用外部世界的能力。查航班要调航班 API，付款要调支付 SDK，浏览器操作要调 Playwright 之类的工具。
  3. 记忆（Memory）：短期记忆靠当前上下文，长期记忆通常靠向量数据库或结构化笔记。
  4. 反思（Reflection）：执行后回头看"这一步有没有用"，决定是继续还是改计划。

把这些串起来的循环就是著名的 ReAct 框架（Reason + Act）：

Thought: 我需要先查航班
Action:  search_flight(departure="PEK", arrival="SHA", date="2026-09-07")
Observation:  返回 3 个航班
Thought:  选最便宜那个
Action:  book_flight(flight_id="MU5102")
Observation:  订票失败：需要乘客信息
Thought:  需要先问用户身份证号
Action:  ask_user("请提供身份证号")
...

你可以看到，每一轮都是 思考 → 行动 → 观察 → 再思考 的闭环。这跟人做事的方式几乎一模一样。

3. 一个具体应用场景

我目前最看好、也最容易被低估的场景是"研究型 Agent"：你给它一篇论文 PDF，它会自动读完、查相关工作、整理对比表格、把要点写成一份摘要报告给你。

具体到一个真实可触达的产品：Anthropic 的 Claude with Computer Use。你可以让它"打开浏览器，去 Hacker News 首页，把今天排名前 10 的帖子标题和链接整理成 Markdown"，它会自己截图、自己点、自己滚动、自己填表单。你能坐在旁边看着它干活。

这种场景有意思的地方是：Agent 不是在替你"思考"，而是在替你"操作"。它把"思考"和"操作"分离开，让思考还是你的，但操作可以并行、可以批量、可以夜深人静时挂机。

4. 容易混淆的问题与边界

  • Agent ≠ Chatbot：Chatbot 只能对话，Agent 必须能动手。一个只能聊天的 AI 不是 Agent。
  • Agent ≠ LLM：LLM 是 Agent 的"大脑"，但 Agent 还需要工具、记忆、规划器这些"身体"。光有大脑不动手，不是 Agent。
  • Agent ≠ Copilot：Copilot（副驾驶）每一步都要你确认；Agent 是"自动驾驶"，只在关键节点问你要权限。
  • "Agentic 工作流"≠"Agent"：很多人把"用 LLM 串起来的几个步骤"叫 Agent，但严格说那只是 LLM Pipeline，不是 Agent。Agent 的核心是"自主决策 + 自主行动"。
  • 边界：自主性越高，风险越大。一个能自己下单付款的 Agent 跟一个只能"建议"的 Chatbot，监管视角是完全不同的。
