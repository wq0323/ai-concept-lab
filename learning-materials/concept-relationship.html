概念关系：Agent · 大模型的上下文 · Skill

配套学习资料：agent.html · llm-context.html · skill.html

一句话总结

大模型（LLM）是引擎，Context 是这台引擎的"桌面"，Agent 把引擎+桌面+工具组装成"能办事的人"，Skill 则是给这个人准备的"岗位手册"。

三者关系是"能力分层 + 知识沉淀"：LLM 提供原生能力，Context 决定每次能用多少能力，Agent 决定怎么把能力变成行动，Skill 决定行动的质量上限。

重点 1：Context 如何影响 Agent 的工作

Agent 的"思考-行动-观察"循环每一步都要消耗上下文。具体影响分三层：

  1. 容量限制：每一步都要把"之前的思考 + 工具返回结果"塞回上下文。当 Agent 走 20 步以后，单步历史可能就占掉大半窗口。
  2. 质量衰减：上面提到的 context rot——模型对靠后内容注意力会下降。这意味着 Agent 后半段决策质量往往不如前半段。
  3. 成本放大：Agent 跑得越久，输入 token 越多，单次任务成本越高。

所以工程上"好 Agent"的一个标志是：能主动管理上下文——定期摘要、丢弃无关历史、把长工具返回裁剪到关键片段。这正是 Skill 能"教"Agent 做的事之一。

# 一种典型的上下文管理策略

rebuild_context = system_prompt + goal + last_3_steps + summarized_history

重点 2：Skill 如何沉淀可复用的任务知识

Skill 的核心价值不是"让 AI 更聪明"，而是"让 AI 干活更一致"。它从三个维度影响 Agent：

  • 流程固化：把"这类任务应该按什么顺序做"写进 Skill，Agent 不用每次自己摸索。
  • 输出规范：把"团队/个人对输出的格式要求"写进 Skill，AI 输出一次就达标，省掉返工。
  • 质量基线：把"自检清单"写进 Skill，让 AI 在交付前自查，避免低级错误。

这就像一家公司：LLM 是新员工的天赋，Agent 是岗位本身，Skill 是岗位手册。手册越细、越贴业务，新员工产出就越稳定。

本仓库里的 concept-explainer 本身就是一个 Skill。它把"如何系统讲清楚一个概念"沉淀成了可复用的流程，本页面的三份 HTML 都是按它的模板生成的——这是一个 Skill 在自我演示。

小结

  • 三个概念是"引擎 / 桌面 / 手册"的层次关系。
  • Context 决定 Agent 一次能走多远。
  • Skill 决定 Agent 每次走得对不对。
  • 好的 AI 系统 = 好的 LLM × 好的 Context 管理 × 好的 Skill 沉淀 × 工具与记忆的合理组装。
